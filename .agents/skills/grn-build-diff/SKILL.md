## Usage

```bash
python3 .agents/skills/grn-build-diff/scripts/run.py \
  --before backend/data/content_digest.before.json \
  --after backend/data/content_digest.json

python3 .agents/skills/grn-build-diff/scripts/run.py \
  --before backend/data/content_digest.before.json \
  --after backend/data/content_digest.json \
  --lock-before backend/data/sources.lock.before.json \
  --lock-after backend/data/sources.lock.json
```

### Parameters
- `--before` (required) — path to the older content digest JSON (produced by
  `backend/scripts/content_digest.py`).
- `--after` (required) — path to the newer content digest JSON.
- `--lock-before` (optional) — path to the older `sources.lock.json`
  (produced by `backend/scripts/export_source_lock.py`).
- `--lock-after` (optional) — path to the newer `sources.lock.json`. Lock
  comparison only runs if both `--lock-before` and `--lock-after` are given.

Neither digest file is generated by this skill — run `content_digest.py`
(and, for source comparison, `export_source_lock.py`) before and after the
build you're investigating, saving each report to a distinct path. This skill
only diffs reports that already exist; it does not touch the database.

### Output

JSON with:
- `tables_changed` — tables present in both files whose digest differs.
- `tables_added` — tables present in `--after` but not `--before`.
- `tables_removed` — tables present in `--before` but not `--after`.
- `row_changes` — for every changed/added/removed table,
  `{before, after, delta}` row counts (`null` where a side lacks the table).
- `sources_drifted` — source keys (`"Name|Version"`) whose `sha256` differs
  between lock files. Only populated when both `--lock-*` args are given.
- `sources_added` / `sources_removed` — source keys present in only one lock
  file.
- `summary` — one-line human-readable recap of the above.

A table can appear in `row_changes` with `delta: 0` if the digest changed but
the row count did not — that means content within existing rows changed, not
that rows were added or removed. Check `tables_changed` together with
`row_changes` rather than relying on either alone.

## What this answers, and what it doesn't

This tells you *what* changed between two builds (which tables, how many
rows, which source hashes drifted) by comparing the digest/lock reports you
hand it. It does not explain *why* a source hash changed, does not re-fetch
or re-verify anything live, and does not know about tables outside whatever
`content_digest.py` happened to cover in each run (e.g. if `--tables` was
used to restrict a run, tables outside that set will look identical here
even if they changed in the database — because they're simply absent from
both reports, not because they're unchanged).

If `--lock-before`/`--lock-after` are omitted, `sources_drifted`,
`sources_added`, and `sources_removed` are empty, and the summary says
source drift was not checked — not that there was none.
